# 第7話 スキル物語 「今夜はミニマックス」と言ったら裏側のレート制限を切り替えてくれる話

## いつ困る？
週の真ん中辺りから「LLMが重いな…」と感じ始める。同じCCのはずなのに、長文要約・複雑なコード生成だけ体感速度が落ちる。ベストなモデルを引き続き使いたいのに、枠が足りない日は待つしかないと諦めがち。回復タイミングを待つ間も思考は止まらず、勿体無い時間が積もる。

## こう言うと起こること
「今夜はミニマックス」「明日の朝までミニマックスにして」「GLMに戻して」「自動に戻して」「プロキシの状態見て」を CC に投げる。裏側の glm-rate-proxy に「今夜はMiniMax・明朝6時まで」と時刻指定でモード切替をPOSTし、対話だけ・裏側だけ・WSL CLI版だけのいずれかを守って切替える。status で現在のモード・残枠・回復時刻を確認でき、明朝6時の自動復帰も予約される。「プロキシ切替」を専門用語無しで扱える。作った LLM プロダクトの枠残りを、スマホから確認できる安心感。

## 何が変わるか
「プロキシが落ちてる？」「上限近い？」を読むことを止められる。明示の言葉だけで動かして、戻す言葉も明示で一発。深夜作業・週末作業・集中セッション前の予習で「軽さが間に合う」状態が自分で用意できる。知らないうちにLLM側を詰めていて本体が止まる事故を、ユーザーの判断で防げる——「重さ」を感じ始めたら声を出す、それだけで世界が軽くなる。

### 仕組み

- 裏側API: `localhost:8787` の glm-rate-proxy が認証トークンを守りつつ ZAI / MiniMax への振り分けを切替え
- 動作 URL: POST `/proxy/mode`（例: `{"mode": "minimax", "until": "06:00"}`・`until` 省略時は手動復帰まで）
- status URL: GET `/proxy/status` で「モード・provider・使用率・明朝の予定」を返す
- 自動切替: GLM週間消費が95%超に達するとプロキシがMiniMaxへ自動切替（緊急モード・ふくけいに無断で切替しない配慮付き）

### 注意点

- 「プロキシ切替」は誰にも見えないサーバー設定変更。言語プロンプト自体は変えない（Gemini・SonnetのMCP経路は別の話）
- 「プロキシの状態見て」と入れれば各LLMの現在接続先・消費率・明朝予定を表示
