# 道具207個の工具箱は導入初日に鍵をかけた話

## 困ったこと

「できあがったアプリの中身を勝手に調べてくれる道具」として話題の工具箱（REA）があったので、私の作業場に新しい道具箱を持ち込んだ。いざ導入しようと箱のふたを開けて数えてみると、工具が**207個**も入っていた。さらに困ったことに、この道具箱は「置くだけで、毎朝作業場の机の上に207個の道具を全部並べる」仕掛けだったのだ。道具の説明書きを壁に貼り出すと、それだけで壁一面（約3.4MB）が埋まってしまう。机は道具で塞がれ、本当の作業をする場所がなくなってしまう。

## どう解決したか

最初の一歩が効いた。**並べる前に、箱を開けて中身を数えた**のだ（道具の一覧を機械に尋ねて実測）。想定よりずっと多い207個。そこで、道具箱は**鍵をかけて棚にしまう**ことにした。必要な日にだけ開けて取り出し、終わればまたしまう。ふだんの作業は、道具箱とは別に用意されていた「一つずつ手に取れる差し込み口」を使う。同じ工具が全部使えるので、何もできない日はない。実は以前、GitHub連携の道具41個入りの箱で机を占領してしまった前例があり、その学習のおかげで今回は部屋に入り込む前に気づけた。

## 何が変わったか

いま作業場の机は、いつも通り空いている。道具が要る日は鍵を開け、終わればまたしまう。それだけの小さな儀式が加わっただけで、道具の能力は一切失わなかった。そして部屋に新しい道具箱を持ち込むときの作法が一つ増えた。**「置く前に、ふたを開けて数える」**。便利さは道具の数では決まらない。今日使う1本がすぐ手に取れるかどうかで決まる——207個の工具箱は、導入初日に鍵をかけたままで正解だった。

<details><summary>▶ 技術的にどう作ったか</summary>

話題のOSS **REA（Reverse Engineer Anything）** を Claude Code 環境へ導入したときの記録。REAは、リバースエンジニアリングの専門工具（Ghidra、JADX 等）をAIエージェントから使えるようにするMCPサーバー＋CLIで、GitHubで史上最速級にスターが伸びたプロジェクト。

導入時、MCPサーバー（AIエージェントに道具を提供する仕組み）として登録したところ、道具一覧を問い合わせる `tools/list` を実行して **207ツール・スキーマ約3.4MB** を広告していることが判明。この環境では、過去にGitHub連携プラグインを41ツール/9.6kトークンのコンテキスト肥大で無効化した前例があるため、「**登録は維持・既定は無効**（作業セッションだけ `/mcp enable` で一時有効化）・**主経路はCLI直叩き**」を採用した。CLIはMCPと同一エンジンで機能差がないため、無効化しても何も失わない。

動作試験は、署名つきの無償APK（F-Droid公式クライアント）で実施し、11,960クラスを6.3秒で解析して証跡IDの発行まで確認した。判断の全文（コマンド・生exit codeつき）は個人のナレッジベース内の判断記録「REA-MCP導入とAndroid解析ハーネス整備」（2026-10-24）を参照。
