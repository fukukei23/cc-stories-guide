第3話 スキル物語 「記録して」と言ったらSSOTに勝手に入る話

いつ困る？

作業が一段落した時「これは後から見直したい」と思う。何をどこに残すのが正解かが分からず、結局メモ帳を開いて散文を書いたり、Slack に貼って埋もれさせたり、Obsidian を直接開いてフォルダ階層を迷ったり。書く場所より書く後で「見当たらない」ことの方が怖くて、記録すること自体を先延ばしにしがちだ。

こう言うと起こること

「記録して」「保存して」「SSOTに入れて」を CC に投げる。裏側では ssot-record スキルが「技術的決定の経緯か、ガイド追記か、ジャケットなプロジェクト固有の作業か」を自動で判定し、保管場所・タグ・関連リンクを機械的に組み立てて、SSOT の日記とインデックスまで連動して書き込んでくれる。「これ残して」「決定事項にして」「構想メモ」と付け加えると、工事の合間のぼんやりした考えを正式な決定に昇格させて残す構想モードに切り替わる。書き手はお題だけ、配置と書き方は全部おまかせ。

flowchart TB
    A["📝「記録して」"] --> B["どこに保存すべきか自動判定"]
    B --> C["判断の記録・設定・日記へ振り分け"]
    C --> D["関連ファイルにもリンクを張る"]
    D --> E["保存して同期まで ✅"]

何が変わるか

「記録しようかな」で止まる日がなくなり、毎セッションの終わりに「記録して」の一言で SSOT が肥えていく。日記・_INDEX.md・関連リンクが自動で繋がるので、後からgrep すれば自分でも意外な切り口から辿れる。「このとき何が背景だったか」が人に頼らず残るようになり、長期プロジェクトの判断根拠が資産として育つ。後輩にも自分にも、覚えていない判断の理由を必ず渡せる。

仕組み

  • 6つのフェーズ（フェーズ0：情報収集 → フェーズ0.8：過去経緯の確認 → フェーズ1：LLM 自身による判定 → フェーズ2：ふくけい承認 → フェーズ3：記録作成+ 逆リンク → フェーズ6：完了報告）で構成
  • 判定の高速ルートは「目的が技術的意思決定か、ガイド追記か、ジャケットなプロジェクト固有作業か」で振り分け（SSOT の特性カタログ準拠）
  • 「01_DECISIONS に書くか・正典と同場所に置くか・別のフォルダか」は LLM が検索して決めて、ッカがアプローチで「なんでこの保管場所か」を 1 文で表明する
  • 関連パターンは「過去 7 日 ∪ 直近 5 件」を温存・連想する「ナナナナ方式」（Nd 補完）で過去記録と接続し、「無い」と決めつける前に必ず再検索する

注意点

  • 01_DECISIONS への手動 Write は PreToolUse hook にブロックされ、スキル経由のフラグが立っている時だけ通過する
  • 構想モード（「これ残して」系）では 01_DECISIONS ではなくバックログ.md の該当タスク直下に📝WIPメモ追加となる（真実のソースを分散させないため）
  • 「ゼロ件」「見つからない」断定は慎重・再検索プロトコル必須
  • 1 セッション内の ssot-record 呼び出し回数はカウンタファイルで数えられ、続けて2回以上記録した時はセッション横断総括（フェーズ7.5）が発火候補になる

由来情報（要約のみ・原文URLなし）

  • 設計正典: SSOTの ~/.claude/skills/ssot-record/SKILL.md（13のフェーズ・関連パターンのN/H/R 3値ルールなど）
  • 運用ルール: SSOTの ~/.claude/rules/_shared/記録.md（「後で書く」禁止・構想の永続化など）
  • 代替先として :ssot-record / :ssot-search / :reflection の並ぶスキル一覧
